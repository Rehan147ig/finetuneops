The Customer Journey

From trace capture to clean dataset, in 9 steps

The end-to-end flow a customer experiences. Steps 1–5 are setup & observation; step 6 is the trigger; steps 7–9 are automated root-cause analysis and one-click recovery.

1
Install the trace capture SDK SDK
Wrap OpenAI / Anthropic / Fireworks / Together SDK calls. Every inference is batched and shipped to the platform.
packages/sdk · wrap-openai.ts · wrap-anthropic.ts
2
Upload the fine-tune dataset data
JSONL upload with automatic versioning. The quality gate runs immediately: duplicate detection, PII scanning, label balance, length & cost checks.
quality-engine.ts · Dataset + DatasetExample
3
Submit a fine-tune job train
The platform launches the job with the customer's provider (OpenAI today; Fireworks + Together on roadmap). A poll worker tracks it to completion.
runtime.ts · launch-finetune · poll-finetune
4
Run evaluation — before & after eval
Auto-eval runs the baseline model and the candidate against a benchmark. Exact-match + Jaccard scoring, using the customer's API key (never the platform's).
auto-eval-engine.ts · EvalRun (before + after)
5
Compare scores compare
The regression engine compares baseline vs candidate, metric by metric, respecting direction (higher-is-better or lower-is-better).
regression-engine.ts · detectRegressionBetweenRuns
6
⚠ Regression detected → alert fires trigger
If the candidate score drops past the threshold, a RegressionAlert is auto-created and a Slack notification is sent. This is the buying trigger — the moment of pain.
RegressionAlert · slack.ts
7
TRA Engine runs 4 root-cause techniques TRA
The Training Regression Autopilot analyses the dataset to find which exact examples caused the drop. Two use an LLM-judge (the customer's key), two are pure statistics.
tra-engine.ts · TraReport + SuspiciousExample
8
Review ranked suspicious examples explain
Each flagged example shows a confidence score, category, impact estimate, and a human-readable reason. No black box — every removal is justified.
/regressions/[id] · TRA report UI
9
✓ One-Click Recovery → clean dataset recover
Bad examples (confidence > 0.6) are removed and a new versioned dataset is created. The customer retrains on the clean data — closing the loop.
recovery-engine.ts · recovery-worker.ts · RecoveryJob

TRA Engine — the core IP

Four techniques that find the bad examples

TRA combines LLM-as-judge (paid, needs the customer's key) with pure statistics (free, always runs). When no credential is present, it runs in limited mode — techniques 3 & 4 only — and tells the user.

⚔️
1 · Instruction Conflict
Finds examples where the input instruction contradicts the output label or response — e.g. the model is taught to refuse when asked for a safe answer.
LLM-judge · 8 per batch
🏷️
2 · Label Noise
Flags mislabeled examples — outputs that don't make sense for the input and would teach the fine-tune the wrong behavior.
LLM-judge · max 40 samples
📑
3 · Duplicate Conflict
Near-duplicate inputs with conflicting outputs. Jaccard similarity clusters rows that bias the model toward one canonical answer.
Statistical · no LLM
⚖️
4 · Class Imbalance
Detects label distributions skewed enough to overfit the model toward one class, undermining minority-case accuracy.
Statistical · no LLM

Architecture Rules — never violate

The load-bearing constraints

These six rules keep the system correct under load and protect revenue & security.

Rule 1 · Queue Pooling
BullMQ Queue instances are cached in a module-level Map. Never instantiate new Queue() in a handler — it exhausts Redis connections.
Rule 2 · No Platform LLM Key
TRA uses the customer's credential via getActiveCredential(). Never process.env.OPENAI_API_KEY. No key → statistical-only (limited mode).
Rule 3 · Atomic Billing
tracesUsed increments use raw SQL with GREATEST(). Never in-memory — the race loses revenue.
Rule 4 · Separate Jaccard
quality-engine and tra-engine each keep their own Jaccard implementation. The separation is intentional — don't unify.
Rule 5 · Dual Worker Registration
Every worker is registered in both runtime.ts and index.ts, or it never processes jobs.
Rule 6 · Workspace Auth
All pages use getServerSession() filtered by workspaceId. Never expose data across tenant boundaries.
